# `src/repo/fs` — plan

First wrapper in `src/repo/`. Wraps `node:fs` behind a single typed
bag, `RepoFs`, exported from `src/repo/fs/index.ts`. Establishes the
pattern every later wrapper (`path`, `proc`, ...) will follow.

## Goal

- One sanctioned way to touch the filesystem from `src/`: `RepoFs.*`.
- `node:fs` and `node:fs/promises` imports banned outside
  `src/repo/fs/` via Biome.
- Tighter types than the stdlib (no `Buffer | string` ambiguity, no
  surprise throws on missing files).
- A DI seam (`Fs` type) so heavy-fs modules can be tested against an
  in-memory stub.

## Look before you leap

Every existing `node:fs` / `node:fs/promises` call site in `src/`:

| File | Symbols |
| --- | --- |
| `src/cli/sim/protocol.ts` | `readdirSync`, `readFileSync`, `renameSync`, `writeFileSync` |
| `src/cli/sim/action/clone_self.ts` | `mkdir`, `mkdtemp` |
| `src/cli/sim/action/cd.ts` | `statSync` |
| `src/cli/sim/assert/dir_exists.ts` | `statSync` |
| `src/cli/cmd/sim_action/main.ts` | `existsSync` |
| `src/cli/cmd/sim_assert/main.ts` | `existsSync` |
| `src/cli/sim/__test__/dispatch.ts` | `existsSync`, `readFile`, `writeFile` |
| `src/cli/sim/__test__/action.test.ts` | `existsSync`, `mkdir`, `mkdtemp`, `rm` |
| `src/cli/sim/__test__/assert.test.ts` | `mkdir`, `mkdtemp`, `rm`, `writeFile` |

The wrapped surface is small and finite: ~10 distinct calls. **Wrap
only what is actually called today.** Add new methods when a real
caller needs them, not before.

## Interface — call sites first

```ts
import { RepoFs } from "@/repo/fs";

// reads
const text = await RepoFs.read(path);                    // string
const names = await RepoFs.readDir(dir);                 // string[]

// writes
await RepoFs.write(path, text);                          // atomic: tmp + rename
await RepoFs.mkdir(dir, { recursive: true });
const tmp = await RepoFs.mkdtemp(prefix);                // absolute path
await RepoFs.rename(from, to);
await RepoFs.rm(path, { recursive: true, force: true });

// inspection
const stat = await RepoFs.stat(path);                    // Stat | null on ENOENT
const exists = await RepoFs.exists(path);                // boolean

// sync escape hatches — only where async won't do
const text = RepoFs.readSync(path);
RepoFs.writeSync(path, text);                            // also atomic
const stat = RepoFs.statSync(path);
const names = RepoFs.readDirSync(dir);
```

Before / after on a real caller (`src/cli/sim/action/cd.ts`):

```ts
// before
import { statSync } from "node:fs";
let isDir = false;
try { isDir = statSync(p).isDirectory(); } catch { /* ENOENT */ }
if (!isDir) throw new Error(`cd: not a directory: ${p}`);

// after
import { RepoFs } from "@/repo/fs";
const stat = await RepoFs.stat(p);
if (!stat?.isDir) throw new Error(`cd: not a directory: ${p}`);
```

The try/catch-for-ENOENT pattern repeats across `cd.ts`,
`dir_exists.ts`, and `parityCheck` in `protocol.ts`. Folding it into
`stat() → Stat | null` removes the boilerplate by design, not by
convention.

## Types

```ts
// src/repo/fs/index.ts

export type Stat = {
  isFile: boolean;
  isDir: boolean;
  size: number;
  mtimeMs: number;
};

export type RmOpts = { recursive?: boolean; force?: boolean };
export type MkdirOpts = { recursive?: boolean };

export type Fs = {
  read(path: string): Promise<string>;
  readDir(path: string): Promise<string[]>;
  write(path: string, contents: string): Promise<void>;
  mkdir(path: string, opts?: MkdirOpts): Promise<void>;
  mkdtemp(prefix: string): Promise<string>;
  rename(from: string, to: string): Promise<void>;
  rm(path: string, opts?: RmOpts): Promise<void>;
  stat(path: string): Promise<Stat | null>;
  exists(path: string): Promise<boolean>;

  readSync(path: string): string;
  readDirSync(path: string): string[];
  writeSync(path: string, contents: string): void;
  statSync(path: string): Stat | null;
};

export const RepoFs: Fs = { /* the only file allowed to import node:fs */ };
```

Decisions:

- `read*` returns `string`. Bytes aren't used in `src/` today; add
  `readBytes` only when the first caller appears.
- `stat` / `statSync` return `null` instead of throwing on ENOENT.
  Other errors still throw. Existing callers all want this contract
  but currently re-implement it with try/catch.
- `write` / `writeSync` are atomic by default (write to `${path}.tmp`,
  then `rename`). `protocol.ts` already does this by hand; centralize
  it once.
- `Stat` is a small typed shape, not stdlib's wide `Stats` class — no
  `Date` objects, no `mode`, no platform-leaky fields until needed.
- `Fs` is a structural type so tests can mock it without inheritance.
  `RepoFs` is the singleton real implementation.

## DI

Default ergonomics: `import { RepoFs } from "@/repo/fs"` and call it.
No DI overhead for the 90% case.

For modules with heavy fs interaction (today: `protocol.ts`), refactor
to take an optional `fs: Fs = RepoFs` parameter. Tests pass a stub:

```ts
import type { Fs } from "@/repo/fs";
import { makeStubFs } from "@/repo/fs/__test__/stub";

const fs = makeStubFs({ ".config/sim.yaml": "actions: {}\nasserts: {}\n" });
const catalog = loadCatalog({ fs });
```

The stub lives at `src/repo/fs/__test__/stub.ts` so it is shared
across tests but absent from the production graph.

## Lint guardrail (Biome)

Add `noRestrictedImports` to `biome.json` and exempt `src/repo/fs/**`
via an override:

```jsonc
{
  "linter": {
    "rules": {
      "style": {
        "noRestrictedImports": {
          "level": "error",
          "options": {
            "paths": {
              "node:fs": "Use RepoFs from @/repo/fs instead.",
              "node:fs/promises": "Use RepoFs from @/repo/fs instead."
            }
          }
        }
      }
    }
  },
  "overrides": [
    {
      "includes": ["src/repo/fs/**"],
      "linter": {
        "rules": {
          "style": { "noRestrictedImports": "off" }
        }
      }
    }
  ]
}
```

This lands in step 4, *after* the migration, so CI is green from the
moment the rule turns on.

## Migration

Order is smallest blast radius first; each step is a self-contained
PR-shaped change.

1. **Add the wrapper.** `src/repo/fs/index.ts` with `RepoFs` and
   `Fs`. No callers change yet.
2. **Add tests.** `src/repo/fs/__test__/index.test.ts` (real tmpdir
   coverage of every method) and `src/repo/fs/__test__/stub.ts` plus
   a conformance test that the stub satisfies `Fs`.
3. **Migrate callers**, in this order:
   1. `src/cli/sim/action/cd.ts`
   2. `src/cli/sim/assert/dir_exists.ts`
   3. `src/cli/cmd/sim_action/main.ts`, `src/cli/cmd/sim_assert/main.ts`
   4. `src/cli/sim/__test__/dispatch.ts`
   5. `src/cli/sim/action/clone_self.ts`
   6. `src/cli/sim/protocol.ts` (largest; refactor to accept optional `fs`)
   7. `src/cli/sim/__test__/action.test.ts`, `assert.test.ts`
4. **Turn on the lint rule.** Add the Biome config above. `bun run
   lint` (or whatever the existing lint script is) must pass.

## Verification

- Unit tests in `src/repo/fs/__test__/` exercise real-fs behavior on
  a `mkdtemp`'d directory.
- A conformance test asserts the stub implements every method of
  `Fs` (compile-time via `const stub: Fs = ...` plus a smoke test).
- An existing simtest exercises the migrated CLI end-to-end against
  a clean clone — no new orchestration needed.
- The Biome rule from step 4 is the durable guardrail. A simtest
  assert that greps for forbidden imports is a possible follow-up if
  Biome ever proves insufficient; not needed for this rollout.

## Out of scope

- Stream APIs (`createReadStream`, `createWriteStream`) — no caller.
- Watcher APIs (`fs.watch`) — no caller.
- File mode / permissions / chmod / chown / symlinks — no caller.
- JSON/YAML helpers (`writeJson`, `readYaml`, ...) — those compose
  `RepoFs.read`/`write` with parsers; introduce when a pattern repeats.
- `node:path`, `node:os`, `node:child_process` wrappers — separate
  plans, same shape.
